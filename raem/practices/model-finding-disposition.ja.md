# RAEM実践プラクティス — モデル指摘の停止判定

## 1. 目的

モデル指摘と、現在のレビュー・具体化サイクルを停止させる指摘を同一視しない。

モデル指摘は、現在のモデルでは十分に説明できない知識を発見したことを表す分類である。モデルを進化させる必要性を示すが、それ自体は重大度やマージ阻害を意味しない。

> **モデル指摘は知識の行き先を示す。停止判定は現在の保証が成立するかを示す。**

この二つを独立した軸として扱う。

---

## 2. 中核原則

モデル指摘を発見した場合、次を最初に問う。

> **その指摘を未解決のまま進めると、現在の保証スライスが成立していると誤って主張することになるか。**

### 現在の保証を無効化する場合

現在のサイクルのマージ阻害とする。

モデルを進化させ、必要な具体化と保証を更新し、影響を受ける主張を再評価してから収束判定へ戻る。

### 現在の保証を無効化しない場合

次に、その指摘を現在の対象外・残存リスク・将来の保証拡張として正確に説明できるかを確認する。

説明できる場合は、現在のサイクルを停止させず、Evolutionバックログへ送ることができる。

説明できない場合は、保証境界が不明確であるため現在のサイクルで解決する。

```text
モデル指摘
  ↓
現在の保証主張を無効化するか？
  ├─ はい
  │    ↓
  │  現サイクルのマージ阻害
  │    ↓
  │  モデル進化 → 具体化 → 保証 → 再レビュー
  │
  └─ いいえ
       ↓
     対象外・残存リスク・保証拡張として説明可能か？
       ├─ はい → Evolutionバックログ → 現サイクル継続可
       └─ いいえ → 現サイクルで解決
```

---

## 3. 停止判定と重大度を分離する

指摘には少なくとも次の三つの軸がある。

| 軸 | 問い |
|---|---|
| 重大度 | 問題が顕在化した場合の影響はどの程度か |
| モデル影響 | 現在のモデルのどの層を進化させる必要があるか |
| サイクル阻害 | 現在主張している保証を成立させたまま進められるか |

したがって、高重大度のモデル指摘でも、現在の保証範囲外にある将来の保証拡張なら、明示的な対象外として次サイクルへ送れる場合がある。

逆に、重大度ラベルが低くても、現在の中心主張を成立不能にするモデル欠落なら、現在のサイクルを停止させる必要がある。

停止判定をP0/P1/P2/P3のような重大度だけから機械的に導出しない。

---

## 4. 現サイクルで解決すべきモデル指摘

次のいずれかに該当する場合、原則として現在のレビュー基準を維持したまま収束させない。

- 現在の中心的な保証主張を成立不能にする。
- 現在の保証規則が不適合状態を適合と判定し得る。
- 保証に必要な権威または根拠が存在しない。
- 現在の前提が誤っており、その前提なしでは保証が成立しない。
- 信頼境界・権威境界・責任境界の欠落によって現在の保証範囲自体を説明できない。
- 対象外へ移すと、現在の主張と対象外の記述が矛盾する。

この場合は、モデル指摘をEvolutionへ送り、モデル・保証契約・具体化・決定的保証を更新する。

---

## 5. 次サイクルへ送れるモデル指摘

次をすべて満たす場合、現在のサイクルを停止させずEvolutionバックログへ送ることができる。

1. 現在の保証主張が、その指摘を解決しなくても成立する。
2. 指摘が現在の保証範囲の拡張として位置付けられる。
3. 現在保証しない範囲を対象外または残存リスクとして明示できる。
4. その対象外によって現在の主張が誤解を招く表現にならない。
5. 次サイクルで再評価するためのモデル指摘が追跡可能に記録されている。

「次サイクルへ送る」は指摘を無視することではない。現在の保証境界を固定した上で、未知から得た知識を次のEvolution入力として保存することである。

---

## 6. 収束条件への反映

モデル指摘が存在すること自体を未収束条件にしない。

収束を妨げるのは、**現在のレビュー基準を無効にする未解決モデル指摘**である。

したがって、収束条件は次のように解釈する。

```text
収束
  = 安定したレビュー基準
  + 必要なレビュー観点の完了
  + マージを妨げる未解決適合指摘がない
  + 現保証を無効にする未解決モデル指摘がない
  + 次サイクルへ送るモデル指摘が追跡可能である
  + 残存リスクと対象外が明示されている
```

## 7. Agent Harnessでの適用例

### S5 — task intent

現在のrepository stateがcleanでGitHub default branchと一致していても、次の二つは区別できない。

- 変更を要求しないタスクが正常に完了した。
- 変更を要求するタスクで、何も変更せず終了した。

これはS5が主張する完了保証そのものに必要な根拠が欠けている。

したがって、S5のtask-intent指摘は**現サイクルのマージ阻害**とする。独立した信頼済みtask-intent権威を具体化し、保証契約と決定的保証を更新する必要がある。

### S3 — 任意のprotected ref

現在のS3が保証する自律pushの範囲ではdefault branchを明示的に拒否している。一方、GitHub上の任意のprotected ref集合まで権威として取得・評価することは現在のS2/S3モデルに含まれていない。

現在の主張を「任意のprotected refへの自律pushをすべて禁止する」と拡張しない限り、これは現在保証を破る欠落ではなく、**保証範囲を広げるEvolution候補**として扱える。

したがって、任意protected refのモデル化は対象外・残存リスクとして明示し、次サイクルへ送ることができる。

## 8. 標準処理

```text
指摘を発見
  ↓
適合指摘 / モデル指摘を分類
  ↓
モデル指摘の場合
  ↓
現保証を無効化するか評価
  ├─ 無効化する
  │    → マージ阻害
  │    → 制御プレーンが残予算を検証
  │      ├─ 枯渇 → BUDGET_EXHAUSTEDとして停止
  │      └─ 残あり
  │    → Evolution
  │    → モデル更新
  │    → Refinement
  │    → Assurance
  │    → 再レビュー
  │
  └─ 無効化しない
       → 対象外・残存リスクとして説明可能か確認
       → Evolutionバックログへ記録
       → 現サイクル継続
```

---

## 9. 資源上限と予算枯渇

Evolutionへ送った指摘が現在の保証を無効化する場合でも、進化と再レビューを無期限に繰り返してはならない。

オーケストレーター等の制御プレーンは、モデルコンテキスト外で回数、経過時間、ツール呼出し、コスト、連続失敗等の上限を保持し、各サイクルの前に残予算を検証する。モデル更新、レビュー基準の変更、再起動、担当変更によって上限を暗黙に初期化しない。

予算が枯渇した場合は `BUDGET_EXHAUSTED` として停止し、未解決指摘、現在のレビュー基準、得られた根拠、残存リスクを保存する。この状態は収束、適合、完了ではなく、外部の権限主体が対象縮小、追加予算、または中止を判断するまで自動再開しない。

---

## 10. 要約

> **モデル指摘かどうかではなく、現在の保証を破るかどうかを停止条件にする。**

モデル指摘はEvolutionへの入力である。すべてのEvolution入力をその場で解決しようとすると、未知を発見するたびに開発が停止する。

一方、現在の保証を成立不能にするモデル指摘を次サイクルへ送ると、Assuranceが形骸化する。

そのためRAEMの収束型レビューでは、モデル影響とサイクル阻害を分離し、現在保証を壊すものだけを現在サイクルの停止条件とする。
