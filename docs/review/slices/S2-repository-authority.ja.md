# S2 — リポジトリ同一性・保護状態・権威状態

## 主張

1. 作業対象リポジトリの同一性を信頼済み入力とGit/GitHub状態から確定する。
2. GitHubの現在の保護状態と最低基準から `READY` / `RESTRICTED` / `BLOCKED` を導出する。
3. 書込み可能なセッションキャッシュを権威として利用しない。
4. 変更操作時に権威状態を再評価し、権威状態を通常承認より先に適用する。

## 権威と責任境界

- 権威: 信頼済み期待リポジトリ、GitHubリポジトリ情報、有効なブランチ規則。
- 観測: ローカルGit状態。
- 前提: S1が成立している。
- 対象外: 任意子プロセスの完全仲介、GitHub/IAM内部実装の完全性。
