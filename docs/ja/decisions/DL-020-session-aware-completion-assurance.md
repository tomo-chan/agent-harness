# DL-020 — 現在の権威的なリポジトリ状態から読み取り専用の完了を判定する

- 日付: 2026-09-06
- 状態: 採用。信頼できる作業状態情報が利用可能になった場合に再評価
- 対象: セッション開始 / 停止 / 決定的な完了保証

## 判断

完了保証では、書込み可能なローカル状態領域へ、権威を持つセッション開始時基準を保存しない。

停止時にリポジトリ保護状態と現在のGit状態を再評価し、次の条件をすべて確認できた場合だけ、成果物向け完了検査を省略する。

- 権威的なリポジトリ保護状態検査によって既定ブランチを確認できる
- 現在のブランチが、その確認済み既定ブランチである
- 未追跡ファイルを含め、作業ツリーがクリーンである
- ローカルの `HEAD` が `origin/<確認済み既定ブランチ>` と完全に一致する

それ以外の状態では、確認不能な場合も含め、通常の決定的な成果物向け完了検査を実行する。

セッション開始時には完了保証に関する説明文を追加してもよいが、権威を持つ完了基準は保存しない。

## 理由

従来の停止時検査は、すべてのセッションに機能ブランチと上流ブランチを要求していたため、既定ブランチ上で行うレビューや調査だけの読み取り専用セッションまで失敗していた。

最初の具体化では、セッション開始時と停止時のGit状態を比較した。しかしモデルレビューにより、その基準状態が、リポジトリコードと同じOS上の利用者権限で書き換え可能なローカル状態領域に保存されていることが分かった。評価対象自身が書き換えられる根拠を、独立した保証根拠として使用することはできない。

修正後の具体化では、停止時に新たに確立した根拠を使い、より限定された問いを評価する。

> 現在のリポジトリは、確認済み既定ブランチ上でクリーンであり、確認済み遠隔既定ブランチと完全に一致しているか。

この条件を満たす場合、ローカルに未完了のリポジトリ成果物は存在しないため、成果物向け完了検査を省略できる。それ以外の場合は通常の完了検査を実行する。

## 具体化・保証・進化モデル上の位置づけ

最初の具体化は読み取り専用セッションの問題を解消したが、保証根拠の信頼境界に違反していた。モデルレビューによってその不一致を発見し、具体化をさらに進化させた。

```text
書換え可能なセッション基準                   -> 権威として使用しない
新たに評価した保護状態 + 現在のGit / 遠隔一致 -> 読み取り専用リポジトリの根拠
それ以外 / 不明                              -> 通常の成果物向け完了検査
```

この主張はリポジトリ成果物の状態に限定する。セッション中に外部システムへの副作用がなかったことまでは保証しない。

## 失敗時の扱い

リポジトリ保護状態、既定ブランチ、現在ブランチ、作業ツリーの清浄性、ローカル `HEAD`、遠隔既定ブランチのコミットのいずれかを確立できない場合、読み取り専用の例外を適用しない。通常の完了検査を実行する。

## 適合保証

回帰検査では次を確認する。

- セッション開始時に権威的な完了基準を保存しない
- 確認済み既定ブランチがクリーンで `origin/<既定ブランチ>` と一致する場合だけ成果物向け完了検査を省略する
- 機能ブランチでは成果物向け完了検査を実行する
- 既定ブランチが汚れている場合は成果物向け完了検査を実行する
- 既定ブランチが遠隔と乖離している場合は成果物向け完了検査を実行する
- 保護状態が確認不能または `BLOCKED` の場合は読み取り専用の例外を適用しない

## 再評価条件

ベンダーまたは信頼済み起動処理が、レビュー作業と成果物変更作業を直接区別できる信頼済みの作業種別、変更結果、取引状態などを提供し、リポジトリコードが変更可能な根拠へ依存せずに判定できるようになった場合に再評価する。
