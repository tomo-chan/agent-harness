# Agent Harness 用語集（Agent Harness Glossary）

## 1. 文書の位置づけ（Document Scope）

本書は、Agent Harness の仕様、具体実装、保証スライスで共有する用語を定義する。製品固有の名称と同じ語がある場合も、本書の定義を共通契約上の基準とする。

用語の定義は概念の意味を固定するものであり、特定の Go / Python の型、パッケージ、CLI フィールドや、特定ベンダーのスキーマを指定しない。振る舞いの規範的な要求は[ツール仕様書](agent-harness-spec.ja.md)、保証主張と根拠は各保証スライスで定義する。

## 2. 用語（Terms）

| 日本語 | 英語・表記 | 本書での意味 |
|---|---|---|
| Agent Harness | Agent Harness / Harness | 自律型ソフトウェア開発エージェントの操作を、ポリシー、信頼境界、能力制御、外部認可、完了条件の中で制御する仕組み全体。単一の実行ファイルだけを指さない |
| エージェント | Agent | 調査、推論、計画、操作提案、成果物作成、未知の問題の探索を行う主体。セキュリティ境界や保証の最終権威ではない |
| サブエージェント | Subagent | エージェントから限定した作業を委譲される主体。独立したセキュリティ境界とはみなさない |
| 制御プレーン | Control Plane | タスク状態、ポリシー判断、承認、予算、完了状態をモデルコンテキスト外で管理する領域 |
| 実行プレーン | Execution Plane | 許可された操作を、サンドボックスやワークロード分離などで能力を制限した環境内で実行する領域 |
| オーケストレーター | Orchestrator | タスク状態、実行順序、承認待ち、予算、再試行、完了判定への遷移を制御する主体 |
| エージェント実行環境 | Agent Runtime | エージェントの推論とツール呼出しを実行し、ベンダーイベントを発行または受信する環境 |
| 行動制御 | Behavioral Control | エージェントへ望ましい行動や手順を伝える指示・規則。単独ではセキュリティ境界とみなさない |
| 意味論的ポリシー | Semantic Policy | 操作の意味、対象、タスク文脈、ライフサイクル状態に基づいて判断するポリシー。ファイルパスやコマンド名だけの静的分類とは区別する |
| 能力制御 | Capability Control | ファイルシステム、ネットワーク、プロセス、外部権限など、実行主体が技術的に行使できる能力を制限する仕組み |
| 外部強制機構 | Independent Enforcement Mechanism | Agent Harness の判断やエージェントの協力とは独立して、サンドボックス、IAM、SCM 規則などを強制する仕組み |
| サンドボックス | Sandbox | ファイルシステム、ネットワーク、プロセスなど、個々のツール実行が利用できる能力を制限する境界 |
| ワークロード分離 | Workload Isolation | コンテナや Pod などにより、エージェントのプロセス、資源、ホスト、他ワークロードへの影響を分離する境界 |
| 信頼境界 | Trust Boundary | 信頼する主体・入力・状態・処理と、信頼せず検証する対象を分ける境界 |
| 信頼された実行環境 | Trusted Runtime | 信頼された実行物、設定、起動経路を確立し、それらをリポジトリやエージェントによる差し替えから保護する実行基盤 |
| 信頼された設定 | Trusted Configuration | 運用者が管理し、リポジトリ管理下の入力やモデル出力から独立して完全性を保つ設定 |
| 信頼基点 | Trusted Root | 実行物や設定を信頼されたものと判断する起点。選択主体、所有権、完全性、更新方法を別途定義する |
| 信頼されたコンピューティング基盤 | Trusted Computing Base / TCB | 対象の保証が正しく成立するために信頼する必要があるコンポーネントと運用境界の集合 |
| 承認ゲートウェイ | Approval Gateway | `ask` と判断された操作について、承認の主体、対象、適用範囲、有効期限を検証し、限定的な権限委譲を管理する境界 |
| フック | Hook | エージェント実行環境のライフサイクルイベントを受け取り、判断や検証を接続する仕組み。製品の失敗時動作によっては単独で強制境界にならない |
| ベンダーイベント | Vendor Event | Claude Code、Codex、Devin などの製品が発行する製品固有のライフサイクルイベントまたはツールイベント |
| ベンダーアダプター | Vendor Adapter | ベンダーイベントとベンダー非依存の共通契約、および共通判断と製品固有応答を相互変換する境界コンポーネント |
| ベンダー統合 | Vendor Integration | ベンダーイベント、アダプター、製品固有応答を共通契約へ接続し、対応能力とバージョン差異を管理する責務 |
| 正規化された操作 | Normalized Action | 操作、対象、文脈をベンダー非依存の形で表したポリシー評価入力。自己申告値と検証済み事実を区別する |
| ポリシー | Policy | 正規化された操作と検証済み文脈から許可、承認要求、拒否を決定する規則と評価条件 |
| ポリシーエンジン | Policy Engine | 正規化された操作と検証済み文脈にポリシーを適用し、判断と理由を算出するコンポーネント |
| ポリシー強制 | Policy Enforcement | ポリシーを選択・評価し、その判断を呼出し側へ返して、許可・承認待ち・拒否の振る舞いへ接続する責務 |
| 判断 | Decision | ポリシー評価結果である `allow`、`ask`、`deny` のいずれか。操作の実行結果とは区別する |
| 許可 | `allow` | 評価した対象と範囲内で操作を進められるという判断。サンドボックスや外部認可を解除しない |
| 承認要求 | `ask` | 有効な外部承認を得て再評価するまで操作を実行しないという判断 |
| 拒否 | `deny` | 対象操作を実行しないという判断。通常の承認によって反転しない |
| 承認 | Approval | 特定の主体、操作、対象、適用範囲、有効期限に対する外部からの限定的な権限委譲 |
| ソースコード管理システム | Source Code Management / SCM | リポジトリ、ブランチ、変更履歴、PR、保護規則、認証・認可を管理する外部システム。GitHub などが該当する |
| リポジトリ識別情報 | Repository Identity | 対象リポジトリを一意に照合するための、検証済みのリポジトリ、リモート、ワークツリーなどの情報 |
| リポジトリ状態 | Repository Posture | ブランチ、保護状態、ワークツリー、未反映変更、リモートなど、操作権限の判断に必要な検証済み状態 |
| 変更権限 | Mutation Authority | 特定のリポジトリ / ワークツリー / ブランチに対して変更を行える、検証済みかつ限定された権限 |
| リポジトリ保護 | Repository Guard | リポジトリ識別情報、リポジトリ状態、変更権限を検証し、誤った対象や保護対象への変更を防ぐ責務 |
| 公開 | Publication | コミット、ブランチ、PR、タグ、リリース、設定などをローカル境界の外へ反映する操作 |
| 公開保護 | Publication Guard | 実際に公開する差分、参照、宛先、認可範囲を検証し、未認可または想定外の公開を防ぐ責務 |
| 制御プレーン変更 | Control-plane Change | ポリシー、フック、CI ワークフロー、権限、配備設定など、Agent Harness や外部強制境界の振る舞いを変更し得る変更 |
| 根拠 | Evidence | 判断や適合主張を支える、出所、対象、取得時点、評価条件を特定できる情報 |
| 完了条件 | Completion Predicate | タスクの完了に必要な、機械検証可能な条件 |
| 完了ゲート | Completion Gate | 完了条件の評価結果を使い、処理の完了や次段階への移行を許可・拒否する強制機構 |
| 完了保証 | Completion Assurance | 根拠と定義済みの評価規則から、完了条件が成立するという主張を確認すること |
| 具体実装 | Concrete Implementation / Realization | ツール仕様を Go、Python、設定、配備、外部制御などで実現したもの。仕様そのものではない |
| 適合保証 | Conformance Assurance | 具体実装が仕様上の要求を満たすという主張を、根拠と定義済みの推論で成立させること |
| 保証スライス | Assurance Slice | S1〜S6 のように、複数の機能・実装・配備境界を横断して特定の保証主張を確認するレビュー軸 |
| モデルレビュー | Model Review | 現在の要求、具体化、根拠、保証規則にまだ表現されていない問題を探索する非決定的プロセス |
| タスク識別情報 | Task Identity | タスク状態、承認、予算、操作、根拠を同一の作業へ結びつける検証可能な識別情報 |
| 実行ファイル検索パス | Executable Search Path | 実行するプログラム名から実体のファイルを探索・選択するために参照するパスの集合 |
| パス解決 | Path Resolution | 相対パス、シンボリックリンク、正規化を考慮し、参照対象の実体と信頼境界内外を確定する処理 |
| フェイルクローズ | Fail Closed | エラーや検証不能のときに、保護対象の操作を許可・完了として扱わない失敗特性 |
| フェイルオープン | Fail Open | エラーや検証不能でも、呼出し元が保護対象の操作を継続し得る失敗特性 |
